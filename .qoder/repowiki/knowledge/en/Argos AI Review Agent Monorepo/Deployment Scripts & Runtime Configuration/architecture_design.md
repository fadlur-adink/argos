Two independent concerns sit side-by-side with no shared code:
- `scripts/` holds standalone utilities. `google-apps-script.js` is a self-contained Google Apps Script that polls a labeled Gmail inbox every minute via a time-driven trigger, extracts unread messages, and POSTs them as `{messageId, subject, body}` JSON to the agent's `/webhook` endpoint (expecting HTTP 202); it marks emails read on success or rejection (422/400) so they are not retried. `test-webhook.sh` is a manual curl smoke test against `http://localhost:8000/webhook`.
- `config/` holds flat JSON configuration consumed by the application at runtime. `config.json` is the live file (with repo mappings under `repositories.<key>.{projectId, localPath}`, optional `publicUrl`, and `telegram` credentials), while `config.example.json` documents the schema with dummy values. There is no loader inside this module — these files are consumed by the parent application.
